# شادابی و سادگی رابط

درخواست مالک: رابط زیبا، راحت و شاداب برای کاربران کم‌آشنا با فناوری، با تصویرسازی سه‌بعدی و رنگ‌های متنوع. لوگوی تازه پس از دریافت جایگزین می‌شود.

برنامه: توسعهٔ توکن‌های روشن/تیره با رنگ‌های هماهنگ؛ تصویرسازی سه‌بعدی محلی برای ورود و خانه؛ میان‌برهای خوانا در خانه؛ کارت‌های آمار رنگی؛ ناوبری موبایل با برچسب؛ نمایش در راهنمای طراحی. فایل‌ها: theme/tokens، components/ui، features/member-screens و mentor-dashboard، locales/fa و دارایی‌های public. جدول و endpoint جدید نیاز نیست.

اعتبارسنجی: typecheck و lint رابط، تست قرارداد طراحی و کنتراست، بازبینی Playwright در ۳۹۰ و ۱۴۴۰ و هر دو پوسته. سیاست‌ها و پاسخ‌های API تغییری نمی‌کنند.

نتیجهٔ پیاده‌سازی: پنج خانوادهٔ رنگ با کنتراست AA در دو پوسته؛ تصویر سه‌بعدی WebP محلی؛ فرم ورود در ابتدای موبایل؛ میان‌برهای خانهٔ عضو/مربی؛ آیکن‌های رنگی و آمار دو ستونهٔ موبایل؛ برچسب‌های پایین صفحه؛ لوگوی دارای نوشته و favicon از نشان بدون نوشتهٔ مالک، همراه با حفظ اصل هر دو فایل و تولید تکرارپذیر دارایی‌ها.

بررسی‌ها: TypeScript رابط و ESLint تمام فایل‌های تغییرکرده موفق؛ سه تست کنتراست/حفاظت cache/نشست موفق. تست مرورگر `tests/visual-refresh.spec.ts` خانه، ورود، آمار مربی، کتابخانه و راهنمای اجزا را بررسی و تصاویر `docs/screens/joy-*` را ثبت می‌کند؛ عرض‌های ۳۹۰/۱۴۴۰ و روشن/تیره، بدون overflow و خطای runtime. در دیتابیس محلی فقط حساب‌های سلسله‌مراتب موجود بودند؛ ورود عضو نمونهٔ seed پایه به همین دلیل ابتدا ناموفق بود. برای تکرار محلی:

```sh
VISUAL_TEST_LOGIN=09120000016 VISUAL_MENTOR_LOGIN=09120000037 npx playwright test tests/visual-refresh.spec.ts
```

بررسی سراسری فعلاً سبز نیست: lint قبلی در فایل‌هایی مثل classes/page.tsx (تعریف تکراری ClassDetail) و مرتب‌سازی importهای چند فایل خطا دارد؛ تست قرارداد طراحی نیز sxهای از قبل موجود در meetings-screen، ops-dashboard و settings-screen را رد می‌کند. این فایل‌ها برای این درخواست تغییر نکردند. migration/seed لازم نبود؛ قرارداد API و دادهٔ دامنه تغییر نکردند. تا رفع موانع بررسی سراسری، این تغییر یک فاز تکمیل‌شده یا commit‌شده اعلام نمی‌شود.
