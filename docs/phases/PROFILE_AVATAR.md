# اصلاح پروفایل و آواتار

- حذف توضیح سربرگ و خروج داخل صفحه، چیدمان دو ستونهٔ جمع‌وجور در دسکتاپ و تک‌ستونه در موبایل، دکمه‌های ذخیره با عرض محتوایی، نمایش فرم تغییر رمز هنگام درخواست.
- مرجع avatar_file_id در person؛ سیاست avatar برای read/update فقط self؛ GET/POST /people/me/avatar و قابلیت/URL در people/me. ذخیره پشت StorageAdapter موجود، بدون URL عمومی.
- کنترل نوع و حجم و ابعاد، تبدیل به WebP کوچک و حذف EXIF با sharp؛ لاگ metadata تغییر عکس.
- آزمون سیاست‌ها، آپلود/بازخوانی، رد فایل نامعتبر/بزرگ، جداسازی افراد؛ typecheck/lint و تصاویر دو عرض/دو پوسته. آزمون زندهٔ S3 به وضعیت سرویس وابسته است.

## نتیجهٔ بررسی

migration توسعه اعمال شد و آزمون PostgreSQL همهٔ migrationها را از صفر و seed را دوبار اجرا کرد. ۴۰۴ آزمون policy/storage پاس شدند؛ آزمون endpoint آواتار (metadata، نوع/حجم نامعتبر، مالکیت، جایگزینی و علامت‌گذاری فایل قدیم) و آزمون مجوز multipart آلبوم پاس شدند. typecheck هر دو برنامه و lint فایل‌های مرتبط پاس شدند. آزمون زندهٔ S3 برای آواتار، بازخوانی تصویر و دانلود کوتاه‌عمر API وضعیت ۲۰۰ داشت. GET مستقیم object پس از رمزگذاری دیگر تصویر قابل decode نیست. در مرورگر، انتخاب فایل از دکمهٔ تغییر عکس، نمایش آواتار در پروفایل/پوسته و باز/بسته شدن Dialog تغییر رمز بدون تغییر رمز حساب بررسی شد.

تصاویر profile-avatar-{390,1440}-{light,dark}.png و profile-password-dialog.png ثبت و از نظر RTL، عرض دکمه‌ها، چیدمان و نمایش عکس بررسی شدند. بارگذاری از دکمهٔ پروفایل پس از فعال‌شدن رمزگذاری نیز انجام شد و تصویر جدید در پوسته/پروفایل نمایش داده شد. تصاویر آلبوم روی S3 در مرورگر تأیید و در mustafa-s3-album.png ثبت شدند. آزمون محافظت همهٔ endpointها و دانلود امضاشده همراه آزمون‌های آواتار/آلبوم (۴ مورد PostgreSQL) پاس شد. سرویس‌های توسعه برای هم‌تراز شدن worker با کد جدید بازراه‌اندازی شدند.
