# داده‌های نمایشی مصطفی حسن‌زاده

فقط محیط توسعه و حساب نمونهٔ `+989120000006` در گروه صفا ۲۰. نام، شناسه، رمز، رضایت و داده‌های هویتی تغییر نمی‌کنند. محتوا صراحتاً آزمایشی است؛ سابقهٔ واقعی فعالیت یا مشاوره نیست.

```sh
npm --prefix api run seed:mustafa-demo
# پس از آماده بودن نوشتن روی سرویس S3:
npm --prefix api run seed:mustafa-demo -- --upload-assets
```

اسکریپت شخص و عضویت مورد انتظار را بررسی می‌کند، خارج از NODE_ENV=development رد می‌شود و ردیف‌ها را با UUIDهای رزروشدهٔ 81000000 می‌سازد. اجرای مجدد محتوای ویرایش‌شده و پیشرفت ثبت‌شده را بازنشانی نمی‌کند. برنامه‌ها و کلاس‌ها گروهی‌اند و برای دیگر اعضای مجاز صفا ۲۰ نیز قابل مشاهده‌اند؛ مشاوره‌ها و پیشرفت مطالعه متعلق به مصطفی‌اند.

- ۵ جلسهٔ کلاس: یک دورهٔ سه‌جلسه‌ای و دو کلاس مستقل؛ فایل صوتی واقعی ندارند.
- ۴ کتاب در سیر عمومی؛ وضعیت نمونه: یک کتاب تمام‌شده، یکی در حال مطالعه، دو کتاب شروع‌نشده (۲۵٪).
- ۲ خلاصهٔ مشاورهٔ ساختگی بدون یادداشت خصوصی.
- ۲ جلسهٔ نمونه با مسئولیت و موعد برای مصطفی.
- ۲ اردوی نمونه، گذشته و آینده، با اطلاعیهٔ وسایل؛ هیچ تراکنش واقعی ایجاد نمی‌شود.
- ۳ اعلان درون‌برنامه‌ای برای خود فرد.
- ۳ تصویر کتاب/طبیعتِ ساختگی در seed-assets/mustafa؛ عکس شخص واقعی استفاده نشده است.

## بررسی در ۱۴۰۵/۰۸/۱۲

تمام پاسخ‌های کلاس، کتابخانه، مشاوره، جلسه و اردو با حساب خود مصطفی از API وضعیت ۲۰۰ داشتند. کتابخانه ۴ کتاب و ۲۵٪ برگرداند. دورهٔ سه‌جلسه‌ای و انتخاب جلسه در مرورگر بررسی شد؛ تصویر کلاس و کتابخانه در docs/screens/mustafa-demo-* ثبت شد.

S3: HEAD باکت و ListObjects موفق بود؛ اما PutObject از SDK، آپلود مستقیم با URL امضاشده و آپلود PNG همگی 500 InternalError از سرویس برگرداندند. تغییر تنظیم checksum نیز مشکل را رفع نکرد. نمونهٔ پاسخ سرویس: RequestId=1793711903428897166، Resource=/safanoor/safanoor-development-probe.png. آپلود تصویر و نمایش واقعی آن از S3 هنوز تأیید نشده است. هیچ مسیر محلی به‌عنوان نتیجهٔ S3 جایگزین نشده و فایل‌های جدیدی که آپلود نشده‌اند به رکوردهای نمایشی متصل نشده‌اند.

مسیر --upload-assets برای ادامه آماده است: سه فایل را می‌فرستد، بایت‌های بازخوانی‌شده را مقایسه می‌کند، جلدهای کتاب/کلاس را متصل می‌کند، سپس با API واقعی آلبوم و حساب مالک گروه عکس‌های نمونه را آپلود می‌کند و نمایش باینری آن‌ها برای مصطفی و منع دسترسی بدون ورود را بررسی می‌کند. بازبینی مرورگر پس از موفقیت این دستور لازم است.

## رفع مانع S3 و آزمون موفق

در ادامهٔ همان روز، آپلود و بازخوانی آواتار از API روی S3 وضعیت ۲۰۰ داد. اجرای --upload-assets نیز موفق شد: سه PNG با مقایسهٔ بایت‌ها بازخوانی و به جلد کلاس/کتاب متصل شدند؛ سه عکس از API واقعی آلبوم با مربی گروه آپلود و با حساب مصطفی بازخوانی شدند. خواندن ناشناس ۴۰۱ گرفت. خطای قبلی ۵۰۰ سرویس در این اجرا تکرار نشد؛ مشخص نشد علت آن در سرویس چه بوده است. مشکل مجوز multipart مستقل از S3 نیز اصلاح شد (شرح در ARCHITECTURE.md).

تصاویر اکنون قبل از ارسال به S3 رمز می‌شوند؛ اسکریپت seed نیز از همین آداپتر استفاده می‌کند. آواتار ساختگی روی حساب مصطفی قرار دارد و تعویض از رابط کاربری آزمایش شده است. عکس‌ها در آلبوم «مطالعه و همراهی — تصاویر آزمایشی» با حساب خود مصطفی در مرورگر نمایش داده شدند (docs/screens/mustafa-s3-album.png).
